# SRS — стриминг по RTMP и SRT

Сервер **SRS** принимает видео (*publish*) и раздаёт его зрителям (*play*) по двум протоколам — **RTMP** и **SRT**. Ниже: как поднять сервер и куда подключаться, чтобы отправить и посмотреть стрим.

---

## 1. Запуск сервера

Отдельно этот сервис не запускается — всё поднимается разом из корня `docs/stream` двойным
кликом по `start.bat` (см. [корневой README](../README.md)). Это просто один из четырёх сервисов
в общем [docker-compose.yml](../docker-compose.yml).

Проверка, что сервер поднялся — открой веб-консоль: <http://localhost:8080/> (или `http://<IP>:8080/` снаружи).

Управление именно этим контейнером (через панель на :8081 либо руками):
```bash
docker logs -f srs    # смотреть логи (выход — Ctrl+C, сервер при этом не останавливается)
docker stop srs       # остановить
docker start srs      # запустить снова
```

> ⚠️ После любой правки `srs.conf` контейнер нужно **пересоздать**, чтобы он перечитал конфиг:
> ```bash
> docker compose up -d --build --force-recreate srs
> ```
> На лету новый конфиг не подхватывается (особенно листенеры RTMP/SRT). Кнопка "Создать и
> запустить" в панели делает то же самое, если контейнер вообще удалили.

## 2. Порты

| Порт  | Протокол | Транспорт | Назначение                 |
| ----- | -------- | --------- | -------------------------- |
| 1935  | RTMP     | TCP       | Отправка и приём стрима    |
| 1985  | HTTP API | TCP       | API SRS (только локально)  |
| 8080  | HTTP     | TCP       | Веб-консоль, HLS, HTTP-FLV |
| 10080 | SRT      | UDP       | Отправка и приём стрима    |

---

## 3. Обозначения

В адресах ниже подставляй свои значения:

| Placeholder | Что это                | Пример                                              |
| ----------- | ---------------------- | --------------------------------------------------- |
| `<IP>`      | IP сервера с SRS       | локально — `127.0.0.1`, снаружи — `203.0.113.10`    |
| `<name>`    | Имя стрима (любое)     | `livestream`, `cam1`, `phone`                       |

## 4. Отправить видео на сервер (publish)

### OBS → по RTMP
- **Сервер:** `rtmp://<IP>:1935/live`
- **Ключ потока:** `<name>`

![[obs_send.png]]

> ⚠️ Если у устройства **одно поле** для URL без отдельного «Ключа потока» (например, **Insta360**) — впиши имя стрима прямо в адрес:
> ```
> rtmp://<IP>:1935/live/<name>
> ```
> Иначе сервер отклонит публикацию с ошибкой `StreamNameEmpty` (имя стрима пустое).

### OBS → по SRT
- **Сервер:** `srt://<IP>:10080`
- **Ключ потока:** `#!::r=live/<name>,m=publish`

![[send_obs_srt.png]]

### Larix → по SRT
- **URL:** `srt://<IP>:10080`
- **streamid:** `#!::r=live/<name>,m=publish`

### Камера → по SRT
- **URL:** `srt://<IP>:10080`
- **streamid:** нет такого поля — оставляем пустым.

> Без streamid сервер подставит значение по умолчанию `#!::r=live/livestream,m=publish`, то есть поток уйдёт в `<name>` = `livestream`. Смотреть его тогда нужно как `live/livestream`.

## 5. Посмотреть стрим (play)

Один и тот же поток SRS отдаёт сразу в нескольких форматах:

| Формат   | Ссылка                                                  | Задержка    |
| -------- | ------------------------------------------------------- | ----------- |
| HTTP-FLV | `http://<IP>:8080/live/<name>.flv`                      | низкая      |
| SRT      | `srt://<IP>:10080?streamid=#!::r=live/<name>,m=request` | минимальная |
| RTMP     | `rtmp://<IP>:1935/live/<name>`                          | средняя     |
| HLS      | `http://<IP>:8080/live/<name>.m3u8`                     | +5–10 сек   |

> 💡 В SRT-ссылке разница только в `m=`: `m=publish` — отправка, `m=request` — просмотр.

### В OBS
Добавь источник **«Источник медиа»**, сними галочку «Локальный файл», впиши адрес (RTMP или SRT) в поле **Ввод**. Включи «Использовать аппаратное декодирование».

![[obs_receive.png|500]]

### В PotPlayer
Открой **«Открыть URL-адрес»** (Ctrl+U) и вставь любую ссылку из таблицы выше.

- **HTTP-FLV / RTMP / HLS** — работают сразу, без настройки. Для плеера удобнее всего **HTTP-FLV**.
- **SRT** — PotPlayer поддерживает `srt://`, но иногда не берёт `streamid` из URL. Если поток не открывается — впиши streamid `#!::r=live/<name>,m=request` отдельно в `Настройки (F5) → Обработка → SRT`, либо просто используй HTTP-FLV.

## 6. Битрейт камеры

Ориентир для отправки с камеры — начни с **~3000 kbps** и подбирай по качеству связи.

| Качество  | H.264     | H.265     |
| --------- | --------- | --------- |
| 1080p/60  | 6000 kbps | 4000 kbps |
| 1080p/30  | 4500 kbps | 3000 kbps |
| 720p/60   | 4500 kbps | 3000 kbps |

## 7. Диагностика по логам

Запусти `docker logs -f srs` и ищи ключевые строки.

### Хорошие признаки (поток идёт)
```
client identified, type=fmle-publish, app=live, stream=insta360   ← публикация принята
got metadata, width=..., height=..., vcodec=7, acodec=10          ← пришли видео+звук
video sh, codec(7, ...)   ← vcodec=7=H.264, vcodec=12=H.265
audio sh, codec(10, ...)  ← acodec=10=AAC
-> HLS ... insta360-1.ts  ← нарезаются сегменты, значит данные текут
```

### Стабильность связи — смотри `ikbps` / `okbps`
```
<- CPB ... ikbps=0,2632,0   ← входящий битрейт от камеры (средний за 30с, за 5с, мгновенный)
```
- Цифры **ровные** (например, всегда ~3000) → связь стабильная.
- Цифры **скачут** (406 → 2632 → 714)f  → канал слабый, камера сама режет качество.
- Длительность HLS-сегментов `dur=` пляшет (67ms ↔ 3728ms вместо ровных ~2000ms) → видео идёт рывками.

**Лечится:** на камере поставить **фиксированный** битрейт пониже (≈1500 kbps) и 720p.
