# enhance — улучшение картинки эфира на NVIDIA

Берёт эфир с телефона из SRS, на видеокарте убирает квадраты и мыло от слабой
связи (и при желании поднимает разрешение), отдаёт обратно в SRS рядом с
исходным. Панель сама переключает медиаисточник OBS на улучшенный поток и
возвращает обратно, если улучшение выключили или воркер упал.

```
SRS live/<стрим> --SRT--> ffmpeg (ремукс) -> PyAV декод -> CuPy YUV->RGB -> NVIDIA VSR
  -> CuPy RGB->NV12 -> NVENC H.264 -> ffmpeg -> RTMP -> SRS live/<стрим>_enh -> OBS (HTTP-FLV)
```

Звук идёт копией с исходными метками времени. Декод, видеокарта и кодировщик
работают конвейером в трёх потоках.

## Требования

- Видеокарта NVIDIA RTX (Turing и новее; режим `STREAMING_*` — Ampere и новее,
  на Turing воркер сам откатится на `HIGH`).
- Docker Desktop с GPU. Контейнеру нужен `NVIDIA_DRIVER_CAPABILITIES=all`: без
  него не пробрасывается `libnvidia-ngx`, и VSR падает на `load()` с кодом -12.
- Образ ~3 ГБ, собирается по кнопке «Скачать» в разделе «Улучшение картинки».

## Режимы (`ENHANCE_TARGET`)

| Значение | Что делает |
|---|---|
| `auto` | до 1080p, если с телефона меньше; иначе очистка в том же разрешении |
| `same` | только очистка (`DENOISE_MEDIUM`) |
| `1080` / `1440` / `2160` | короткая сторона на выходе (режим — по `ENHANCE_STYLE`) |

## Характер апскейла (`ENHANCE_STYLE`)

Действует, только когда разрешение увеличивается; на очистку не влияет.

| Значение | Режим VSR | Что на картинке |
|---|---|---|
| `natural` (по умолчанию) | `HIGH` | как снято: фактура и тонкие линии на месте, квадраты не усиливаются, резкости добавляет мало |
| `sharp` | `STREAMING_ULTRA` | заметно резче лицо и контуры, но тонкие линии выходят «нарисованными», фактура сглаживается, квадраты на смазанных участках усиливаются |

Сравнивали на живом эфире 720p HEVC ~1 Мбит → 1080p (2026-11-12): `HIGH` — 2,2 мс
на кадр, `STREAMING_ULTRA` — 3,5 мс.

## Тонкие настройки

| Переменная | Значения | Что делает |
|---|---|---|
| `ENHANCE_STRENGTH` | `0`…`1`, по умолчанию `1` | сила апскейла: `0` — обычное растягивание (совпадает с бикубиком), `1` — эффект целиком |
| `ENHANCE_CLEAN` | `0`…`1`, по умолчанию `1` | сила очистки от квадратов и шума (`DENOISE_MEDIUM`): `0` — кадр как пришёл |
| `ENHANCE_PRECLEAN` | `0` / `1` | чистить кадр отдельным проходом перед увеличением (+~1 мс на 720p) — апскейл не усиливает квадраты |
| `ENHANCE_SMOOTH` | `0` / `1` | плавность: между соседними кадрами дорисовывается промежуточный, частота вдвое выше (24 → 48, 30 → 60). При 50+ к/с на входе не включается |

Сила очистки — именно параметр силы, а не уровни `DENOISE_LOW…ULTRA`: уровни — это
размер модели (`ULTRA` в 3,5 раза дороже `MEDIUM`, на глаз не отличается), а `LOW`
на замере менял кадр сильнее, чем `MEDIUM`.

Плавность (`VideoFrameGeneration`) работает на входном разрешении, до увеличения, в
режиме `LOW`: 1 мс на кадр, худший кадр 2,3 мс. `MEDIUM` в среднем 2,5 мс, но
срывается на отдельных кадрах до 70–250 мс и в живом воркере держался на 20+ мс —
эфир начинал отставать. Весь конвейер 720p24 → 1080p48 (`HIGH+x2`) — 9–14 мс
видеокарты на пришедший кадр при бюджете 42 мс. Настоящий кадр придерживается на
полкадра (~20 мс), чтобы дорисованный и настоящий уходили зрителю равномерно, а не
парами. В строке `STATS` при плавности `fps` — кадры на выходе, `gpu_ms` — на один
пришедший кадр.

## Замеры (RTX 4070 Ti, 2026-11-10)

| Вход | Выход | к/с | видеокарта, мс/кадр |
|---|---|---|---|
| 720p30 | 1080p | 30 | ~6 |
| 1080p60 | 1080p (очистка) | 60 | ~4 |
| 1080p60 | 1440p | 60 | ~9 |
| 1080p60 | 4K | 60 | ~12 |

Добавленная задержка относительно исходного потока — в среднем ~70 мс.

## Запуск руками (в обход панели)

```bash
docker build -t bondcast-enhance:latest .
docker run --rm --gpus all --network bondcast-net -e ENHANCE_SOURCE=<стрим> bondcast-enhance:latest
```

Панель сверяет образ с исходниками по метке `bondcast.enhance.fingerprint`, которую
сама ставит при сборке. Образ, собранный руками, метки не несёт — панель предложит
«Обновить» и пересоберёт его сама (слои из кэша, это быстро).

В логе каждые 5 с строка `STATS fps=… in=… out=… gpu_ms=… lag_ms=…` — её же
читает панель. Растущий `lag_ms` значит, что воркер не успевает за эфиром.
