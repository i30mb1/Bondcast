# Bondcast Stream — стриминг-стек одним запуском

Серверная часть для приложения **Bondcast**: принимает бондинг-стрим с телефона
и раздаёт его дальше (в OBS, зрителям, куда угодно), а по желанию ещё и
накладывает живые субтитры «ведущий/гость» поверх эфира в OBS. Сервисы
поднимаются разом одной командой (или двойным кликом), управляются из одной
веб-панели: **SRS** (принимает и раздаёт видео), **srtla-rec** (бондинг с
телефона), сама **панель** и опционально **asr-obs** (субтитры, GPU).

```
телефон (N линков) ──UDP:5000──▶ srtla-rec ──SRT──▶ SRS :10080 ──▶ зрители (RTMP/SRT/HTTP-FLV/HLS)
                                                       ▲    │
OBS ──RTMP:1935 или SRT:10080──────────────────────────┘    └─(опц.)─▶ asr-worker ──▶ overlay :8082 ──▶ OBS Browser Source (субтитры)

Панель на :8081 управляет всеми контейнерами и показывает адреса.
```

> Если тебе просто нужно поднять сервер и не хочется разбираться с Docker и
> терминалом — скачай установщик: [BondcastStream-Setup.exe](https://github.com/i30mb1/Bondcast/releases/latest/download/BondcastStream-Setup.exe)
> (кнопка на [лендинге](index.html)), он делает всё из шагов ниже сам. Этот
> README — для тех, кто хочет запустить вручную, собрать установщик заново
> или посмотреть исходники.

## Быстрый старт

1. Установи [Docker Desktop](https://www.docker.com/products/docker-desktop/), если ещё не стоит.
2. Двойной клик по **`start.bat`**.
   - Нет Docker — откроется страница с подсказкой, что установить.
   - Docker не запущен — откроется страница "запусти Docker Desktop".
   - Всё ок — поднимутся основные сервисы (без субтитров, они опциональны) и через несколько секунд
     откроется браузер на панели (`panel/public/index.html`, порт `:8081`).
3. Панель — одна страница с вкладками, без деления на «быстрый старт» и «расширенную панель»:
   **Старт и подключение** (статус сервисов, виден ли порт снаружи, QR и SRT-строка для OBS),
   **Сервисы** (Start/Stop, статус), **Стрим и оверлей** (субтитры asr-obs, оформление) и
   **Диагностика** (превью потока, логи, битрейт). Переключатель **Просто/Продвинуто** в шапке
   прячет вкладку «Сервисы» и тонкие настройки для менее технического стримера — сам факт того,
   что сервисы подняты и порт виден снаружи, показан всегда, на первой вкладке.
4. Проверка порта (шаг «виден ли порт снаружи») бьёт наружу через сторонний **check-host.net**
   (публичный, бесплатный, без ключа) — своей внешней точки для проверки нет, поэтому просим её
   оттуда. Уходит только `IP:порт`, ничего чувствительного (пассфразы/ключей).

Архив можно распаковать в любую папку на любой машине с Docker — путей, зашитых в код, нет
(см. `PROJECT_ROOT` в [panel/server.js](panel/server.js), если интересно как это работает).

## Структура

| Папка / файл | Что это |
|---|---|
| [`docker-compose.yml`](docker-compose.yml) | Единая точка правды — все сервисы и их параметры |
| [`start.bat`](start.bat) | Точка входа: проверка Docker → запуск → открыть панель в браузере |

| [`asr-obs/`](asr-obs/README.md) | Опционально: субтитры «ведущий/гость» (`asr-worker` + `overlay`), GPU, поднимается по кнопке в панели |

Подробности по каждому сервису (протоколы, порты, диагностика по логам, битрейты) — в README
соответствующей папки.

## Сборка установщика (.exe)

`installer/setup.iss` компилируется [Inno Setup 6](https://jrsoftware.org/isdl.php)
(`winget install JRSoftware.InnoSetup`) и копирует в установщик тот же состав файлов,
что и ручной запуск через `start.bat` (см. список `Source:` в самом `.iss`):

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\setup.iss
```

Результат — `installer/dist/BondcastStream-Setup.exe` (не в git, см. `.gitignore`). Файл нужно
вручную залить в [GitHub Releases](https://github.com/i30mb1/Bondcast/releases) под этим
именем — на него ссылаются и `index.html`, и сам установщик (проверка обновлений отсутствует).

## Порт не виден снаружи — почему

Панель показывает «виден ли порт снаружи» на вкладке **Старт и подключение** и там же сама
называет причину: она не просто пингует порт извне, а сверяет несколько независимых фактов и
выдаёт первую подходящую причину вместе с инструкцией и (где возможно) кнопкой-починкой.
Доверяй ей больше, чем факту «`docker ps` показывает порт»: контейнер может слушать порт у себя
и всё равно быть недоступным снаружи.

Полный список причин, от ближней к дальней — в этом же порядке их проверяет панель
(`diagnoseClosed()` в [panel/public/app.js](panel/public/app.js), факты собирает
`GET /api/reachability` в [panel/server.js](panel/server.js)):

**На самой машине** (панель определяет точно, спрашивая Docker):

1. **Docker не отвечает** — пока движок не поднялся, порт слушать некому.
2. **Контейнер удалён** (`docker rm`) — в панели есть кнопка «Создать и запустить».
3. **Сервис остановлен или упал** — кнопка «Запустить». Если он в рестарт-цикле, смотри лог
   на вкладке «Функции» → «Диагностика».
4. **Порт на хосте занят другой программой** — Docker не смог его пробросить и контейнер не
   стартовал (`Bind for 0.0.0.0:5000 failed: port is already allocated`). Кто занял:
   `Get-NetUDPEndpoint -LocalPort 5000` / `Get-NetTCPConnection -LocalPort 1935 -State Listen`,
   дальше `Get-Process -Id <OwningProcess>`.
5. **Порт зарезервирован Windows** под Hyper-V/WSL — отдельный случай предыдущего, с другой
   ошибкой (`An attempt was made to access a socket in a way forbidden by its access
   permissions`) и другим лечением: `netsh int ipv4 show excludedportrange protocol=udp`,
   затем `net stop winnat` + `net start winnat`. Порт `5000` попадает в резерв особенно часто.
6. **Контейнер работает, но порт не опубликован** — так бывает у контейнера, созданного руками
   без `-p`. Лечится запуском ярлыка: он пересоздаёт всё по `docker-compose.yml`.
7. **Сервис не слушает на самой машине** — проверяется дозвоном контейнер → хост
   (`host.docker.internal`, только TCP). Для `4455` это прямой диагноз: OBS не запущен или в
   нём выключен WebSocket-сервер.

**Проверяется не тот адрес:**

8. **Адрес сменился после старта.** `HOST_IPS` снимается один раз, при запуске ярлыка; у
   динамического IP провайдер меняет адрес сам. Панель сравнивает зафиксированный адрес с тем,
   что интернет видит сейчас, и говорит об этом. Лечится перезапуском ярлыка, надолго — DDNS
   или статический IP.
9. **Включён VPN** — проверяется адрес VPN-выхода, а не твой; проброс на роутере к нему не
   относится вообще. Определяется по флагу `proxy` у ip-api.com (тот же приём в `start.bat`).

**Дальше по пути наружу:**

10. **Мобильный интернет (CGNAT)** — у сотового оператора абонент за общим NAT, проброс
    невозможен в принципе, сколько ни правь роутер. Определяется по флагу `mobile` у ip-api.com.
    Варианты: проводной интернет, услуга «белый IP» у оператора, приёмник на арендованном VPS.
11. **Проба дошла и получила отказ** (`Connection refused`) — путь снаружи работает, но на том
    конце никто не слушает: правило проброса ведёт не на ту машину (LAN-адрес уехал — нужна
    DHCP-резервация) или указан не тот протокол.
12. **Серый IP / двойной NAT** — сервер не может это увидеть сам: снаружи абонент за CGNAT
    выглядит так же, как за белым адресом. Проверяется вручную: WAN-адрес на странице «Статус»
    роутера. Если он начинается на `100.64`…`100.127`, `10.`, `172.16`…`172.31`, `192.168` —
    адрес серый: либо перед роутером стоит модем провайдера (пробрасывай на обоих или переведи
    модем в bridge), либо тебя посадил за общий NAT провайдер (нужен «белый IP» отдельной
    услугой, либо приёмник на VPS).
13. **Фаервол Windows или антивирус.** Частое: сеть помечена как «Общедоступная»; при первом
    запуске Docker окно брандмауэра закрыли крестиком (Windows запомнил это как запрет для
    `com.docker.backend.exe`); сторонний антивирус со своим сетевым экраном поверх системного.
14. **Провайдер режет входящие** — редкое, остаётся когда всё выше проверено.

Панель отделяет «дело в этом порте» от «не пускают вообще»: если снаружи виден хоть один TCP-порт,
то серый IP, двойной NAT и «фаервол режет всё подряд» отпадают, и остаётся правило именно для
проблемного порта.

### Ошибки в самом правиле проброса

Когда порт нужно пробросить (сервер поднят у одного, а стримит другой через интернет), нужны
`5000/UDP` (бондинг) и/или `10080/UDP` (прямой SRT).

Панель даёт кнопку **«Открыть настройки роутера»** прямо в инструкции — с реальным адресом
роутера, а не с угаданным: его считает `get-gateway-ips.ps1` (шлюз по умолчанию из таблицы
маршрутов, только физические адаптеры) и `start.bat` передаёт через `GATEWAY_IPS`. У всех он
разный — `192.168.1.1`, `192.168.0.1`, `192.168.31.1`, `10.0.0.1`. Панель ещё и проверяет
дозвоном, по какой схеме открывается веб-морда (80 → `http`, иначе 443 → `https`, иначе 8080),
чтобы не давать мёртвую ссылку. Если `GATEWAY_IPS` не передан (панель подняли не ярлыком),
адрес выводится из LAN-адреса заменой последнего октета на `1` и помечается как приблизительный.

Логин с паролем панель, само собой, не знает — в инструкции есть отдельный блок: где их искать
(наклейка снизу роутера, типовые `admin/admin`), что делать, если пароль меняли, и чем грозит
кнопка Reset. Если роутер выдал провайдер, часто быстрее попросить проброс у их поддержки.

Правило есть, а порт всё равно закрыт — смотри сюда:

- **Внешний (Public/WAN) порт не совпадает с внутренним (Local) портом.** В некоторых
  роутерах это два независимых поля — легко создать правило «Local Port 10080», забыв
  поменять «Public Port» с уже существующего `5000` (скопировали строку и поправили не всё).
  Итог: снаружи открыт `5000`, а `10080` не проброшен никуда, хотя строка в таблице для него
  вроде бы есть.
- **Заполнено поле «Remote Host» (ограничение по IP источника).** Если туда вписан
  какой-то конкретный адрес (например, по ошибке — собственный публичный IP роутера) —
  роутер будет принимать входящие подключения только с него и отбрасывать всё остальное,
  включая реальный трафик со телефона стримера. Для стрима с произвольного адреса это поле
  нужно оставить пустым.
- **Протокол** — для SRT это всегда UDP; если в правиле стоит только TCP, подключение
  не пройдёт.
- **Внутренний IP уехал** — если у машины с Docker нет статического LAN IP или DHCP-резервации,
  адрес может смениться после перезагрузки роутера/компа, и старое правило будет указывать
  в никуда. Панель показывает текущий LAN-адрес прямо в инструкции (`LAN_IPS`, считает
  `get-host-ips.ps1` из `start.bat`).

### Насколько можно верить зелёному «порт открыт»

Проверка идёт через сторонний check-host.net, и у неё разная сила по протоколам:

- **TCP** (`1935`, `8080`, `4455`) — вывод твёрдый в обе стороны: коннект либо удался, либо нет.
- **UDP** (`5000`, `10080`) — твёрдое только «закрыт». Замерено вживую: и открытый UDP-порт
  (`8.8.8.8:53`), и заведомо закрытый (`8.8.8.8:12345`) отвечают одинаково — молчанием. То есть
  «открыт» по UDP на самом деле означает «нам не прислали ICMP-ошибку», а молчаливо дропающий
  фаервол выглядит ровно так же. Зато «закрыт» доказателен: ICMP port unreachable кто-то
  прислал, значит пакет дошёл. Поэтому в кросс-проверке «а виден ли снаружи хоть один порт»
  панель опирается только на TCP-результаты.

## Панель без Docker-контекста

Если Docker уже поднят вручную (`docker compose up -d --build`) не через `start.bat` — большая
часть панели (Start/Stop, логи, адреса) работает как обычно. Не сработает
только кнопка «Создать и запустить» для удалённого (`docker rm`) контейнера — ей нужен
`PROJECT_ROOT`, который выставляет `start.bat`. В этом случае просто пересоздай сервис вручную:
`docker compose up -d --build <имя-сервиса>`.

## Требования и ограничения

- Пока только Windows (`start.bat` использует PowerShell и `curl.exe` из Windows 10+).
- Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/) — бесплатный для
  личного использования и небольших компаний; для более крупных бизнесов у Docker своя
  платная лицензия ([подробности у Docker](https://www.docker.com/pricing/faq/)).
- Субтитры (`asr-obs`) — опционально, нужна NVIDIA GPU с CUDA; без неё сервис не соберётся/не
  запустится (CPU-фолбэк описан в [asr-obs/README.md](asr-obs/README.md)).
- Сборка `.exe`-установщика — отдельный шаг, нужна только для релиза, не для обычной работы
  (см. «Сборка установщика» выше).
